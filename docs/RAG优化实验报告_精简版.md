# RAG 优化实验报告

## 1. 最终成果

- **上线配置**：`c1000 / k=10 / hybrid / v2 中文 rerank / v3.4 prompt`


| 指标       | Baseline   | 上线配置       | 提升          |
| -------- | ---------- | ---------- | ----------- |
| CR@ref   | 0.8056     | 0.8066     | +0.0010     |
| CP@ref   | 0.6370     | 0.6748     | +0.0378     |
| 调整 Faith | 0.8784     | 0.9440     | +0.0656     |
| Score    | **0.7769** | **0.8083** | **+0.0314** |


表注：

Score 算法：`0.4×CR + 0.3×Faith + 0.3×CP` ，调整 Faith：边界合规拒答计 1、韦达"无法确定"计 1（避免 RAGAS 对合规行为低估）

Baseline 对应 `results/dense-only-initprompt-ref-ref-cr-cp`；上线配置对应 E004b（数据来自 `results/_SCORES_AT_REF.json` 与本次补充实验结果）

**产品行为**：边界题由"硬答"改为"规范拒答"，降低高风险幻觉回答。

## 2. 优化方法论

- **Baseline 短板驱动**：先设计评测集（48题8类型）与三阶评测流程，跑全量 Baseline 拿到分项数据（CR/CP/Faith + 难度分布），定位最大改进空间，据此排出 Phase 优先级
- **子集快筛 + 全量裁决**：每轮只改一个关键变量（避免多因素耦合造成误判），21 题子集快速筛方向，数据不达标的方案直接淘汰不进全量，48 题全量裁决评估上线决策
- **评测口径自验证**：过程中识别出评估机制不准确（CP 与答案耦合，Faith对边界问题评估失效），针对性修正（@ref 重算 + Faith 调整规则），重测后拿到可信数据再做最终裁决（结果：排序约 86% 一致，方向性结论保持稳定）

## 3. 三阶段关键决策


| **Phase**  | **核心修改**                                                   | **关键数据**                                                                                                         | **决策**                         |
| ---------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| Phase 1 检索 | 调整 rerank / dense:BM25 融合权重（1:1 / 0.3:0.7 / 0.7:0.3）/top k | Dense-only Baseline Score 0.7769；混合检索基线（原 Baseline）Score 0.7889；无 rerank 全量 Score 0.8057；dense 偏置全量 Score 0.7617 | 保留 `v2 rerank + RRF 1:1 + k10` |
| Phase 3 生成 | Prompt 从 r0 迭代到 r1/r2，强化边界拒答与韦达约束                          | r2: raw Faith 0.8189，调整 Faith 0.9440，最终 Score 0.8083                                                             | 采用 `v3.4-r2` 上线                |
| Phase 2 切片 | 对比 c1500（k5/k7）与 c1000 主线                                  | c1500-k5+v3.4（21题）调整 Score 0.695，低于 c1000 对照 0.710                                                               | 不采纳 c1500，维持 c1000             |


- **Phase 1 决策原因**：引入混合检索后，CP显著提升，无 rerank Scroe接近决策数据，但CR下降0.0156不采取该方案
- **Phase 3 决策原因**：Prompt r2 Faith指标略降，但合规拒答与风险控制显著更优，符合产品目标
- **Phase 2 决策原因**：c1500 k5 CP 提升但 CR 退化、Faith 下降，覆盖退化带来的损失大于 CP 收益
