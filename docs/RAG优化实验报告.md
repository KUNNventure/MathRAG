## 1. 引言

### 1.1 项目背景

项目为人教版初中数学 RAG 优化，当前切片规模3000chunks+。评测使用 48 题 Golden Set，包含知识定位、跨章节关联、边界拒答与公式场景（含韦达相关问法）。

### 1.2 优化目标

Baseline（Dense-only naive RAG，无 rerank）的核心短板：

- Context Precision 偏低，检索噪声较多
- 边界题与不确定题容易“硬答”，导致产品风险高

目标是同时提升“检索有效性 + 产品合规性”，并建立可复用的评测与复盘闭环。

### 1.3 方法论概述

- 先设计好评测集（Golden Set）和完整的评估流程
- 进行全量Baseline测试，得到初版数据，根据数据找到优化幅度大的环节，确定后续实验流程
- 分阶段单变量对照：检索参数（Phase 1）→ 生成 Prompt（Phase 3）→ 切片粒度（Phase 2）
- 错误驱动优化：先定位评测口径与行为问题，再定向改 Prompt 与检索
- 统一裁决：最终以同口径、同答案可合成的指标进行上线判断

### 1.4 文档导航

- 本文按 最终配置 + 评测过程 + 复盘反思 + 数据档案 顺序组织
- 全量数据档案见文章末尾
- 机读 JSON：
  - `实验汇总_MASTER.json`
  - `SCORES_AT_REF.json`

## 3. 评测标准（D1-D4）

### 3.1 评测口径修复故事

在全量测试最终配置时发现数据偏低，与预期不符。验证后发现初版 CR/CP评测使用 `ContextPrecisionWithoutReference`，对生成答案存在耦合：当答案措辞变化时，CP 波动可能掩盖检索本身质量。为保证准确有效，后续切换到 `@reference` 模式 CR/CP（`rescore_ragas_cr_cp.py`）对全流程进行重新测试。

发现：切换 @ref 后系统性表现为 **CR 上升、CP 下降**（p1.1 子集约 +14% / −11%），少数实验绝对值变化较大但**排序约 86% 一致**。

重测结果：原配置数据最优，方向性结论不变。

### 3.2 D1-D4 决策表


| 决策  | 内容                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------ |
| D1  | CR/CP 最终以 `@reference` 指标为准                                                                                  |
| D2  | 综合 Score 仅允许“同次、同答案”合成                                                                                       |
| D3  | Faith 采用产品向调整规则（边界拒答、韦达“无法确定”计 1）                                                                            |
| D4  | 旧口径 CR/CP 保留作历史记录，不作最终衡量依据                                                                                   |
| D5  | 综合评分机制：全量用 `Score=0.4*CR+0.3*Faith+0.3*CP`，子集用 `Score_p=0.6*CR+0.4*CP`；若方向冲突，以全量 Score + D3 产品约束裁决；禁止跨运行拼接分数 |


### 3.3 合法 Score 与禁止拼接


| 组合                       | 合法  | 说明                                       |
| ------------------------ | --- | ---------------------------------------- |
| E001b                    | ✅   | @ref CR/CP + v0 rerank/v1 同答案 Faith = 0.7889 |

### 3.4 子集选择逻辑与综合评估标准

子集（21题）用于快速筛选方向，提高实验效率。不用于直接下上线结论。选择逻辑分三层：

1. **同口径可比**：同一批题、同一流程、同一口径（优先看 `@ref` 的 CR/CP 与 `Score_p`）。
2. **相对收益**：优先保留在子集上有稳定增益且机制可解释的方案（例如 rerank 改善中文语义匹配）。
3. **迁移验证**：子集胜出仅表示“进入下一轮”，必须经过 48 题全量裁决才可采纳。

综合评估标准：

- **主指标**：`Score = 0.4*CR + 0.3*Faith + 0.3*CP`（用于综合验证）
- **次指标**：`Score_p = 0.6*CR + 0.4*CP`（用于检索阶段横向排序）
- **辅助指标**：CR/CP 拆开看，避免“单指标拉高掩盖另一项退化”
- **决策输出**：每个候选只允许三种状态：`采纳进入全量 / 保留对照 / 不采纳`
- **淘汰条件**：出现明显偏置（如子集局部增益但机制不稳）或工程收益不成立

## 4. 实验顺序安排：1 - 3 - 2

### 4.1理由

- RAG系统流程固定：上游数据影响下游，优先修改上游：1.方便定位问题 2.不受其他流程干扰
- 相关性权衡：提示词独立性高，改动提示词对其他环节影响小
- 收益确定性：Phase 3 对产品风险（误答/编造）收益更直接且可快速验证

### 5.5 关键发现

- v2 中文 rerank 能改善中文数学问法与教材片段匹配，减少语义错配
- 融合权重偏置（0.7:0.3）在子集数据表现更优，但全量泛化失败，对更大范围数据处理能力弱，不够均衡
- 无 rerank 方案出现“子集不差、全量落后”，说明稳定性不足，不适合作上线主路径

### 5.6 未解硬伤

韦达定理别名与变体问法仍有召回不稳问题，需要在查询改写与同义归一化层补强。

## 6. Phase 3：生成 Prompt 调优

### 6.1 决策摘要

最终上线 `v3.4-r2`，核心收益在产品行为质量（边界拒答、控幅、不编造）而非综合指标。

- RAGAS 局限：合规拒答可能被 raw Faith 低估，调整规则更贴近产品目标

## 8. 工程合理性与面试口径

### 8.1 数字 vs 常见基线


| 维度       | 常见有效提升        | 本项目                      |
| -------- | ------------- | ------------------------ |
| 检索 @ref  | +0.02 ~ +0.05 | Score_p +0.0025（小幅但方向正确） |

### 8.2 关键叙事点

- 发现 CP 耦合问题 → 修复口径 → 重验闭环，保证结论可信
- Phase 2 出现收益不稳后及时止损（保留 c1000 主线）
- v3.4 在 raw Faith 不占优时，仍因产品行为质量而上线

### 8.3 面试 FAQ 预演

- CR 怎么评：统一使用 `@reference` 重算，避免答案风格干扰
- 踩过哪些坑：CP 耦合、子集外推全量、不同来源 Faith 拼接
- 为什么 Phase 3 先于 2：低成本快验证，先解决产品风险
- 为什么不用更大 chunk：覆盖与召回稳定性下降，收益不达标

### A. 实验 ID 命名规范

- `E00x`：全量关键里程碑

### B. 目录结构与文件位置

- 实验结果：`results/<run_id>/report.json`
- 汇总机读：
  - `results/_MASTER_SUMMARY.json`
  - `results/_SCORES_AT_REF.json`
- 桌面镜像：
  - `实验汇总_MASTER.json`
  - `SCORES_AT_REF.json`

### C. 关键脚本说明

- `scripts/rescore_ragas_cr_cp.py`
  - 将已有运行重算为 `@reference` CR/CP，输出 `*-ref-cr-cp`
- `scripts/patch_ref_scores_with_faith.py`
  - 将 Faith（含调整值）补丁到 `@ref` 报告，并计算 `score_full`
- `scripts/run_ref_eval_pipeline.py`
  - 一键流程：`evaluate --no-metrics` → `@ref CR/CP` → `Faith` → `patch score`
